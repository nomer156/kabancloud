# 🚀 Руководство по развертыванию KabanCloud на отдельном VPS (Ubuntu / Debian)

> **Цель**: Запуск автономного сервера корпоративной канбан-доски «Уфанет» на отдельном виртуальном сервере (VPS) с круглосуточной работой, автозапуском через PM2, реверс-прокси Nginx и автоматической авторизацией по именам рабочих станций (`vlxproject00` .. `vlxproject99`).

---

## 🖥️ 1. Требования к VPS

- **Операционная система**: Ubuntu 22.04 LTS / Ubuntu 24.04 LTS (или Debian 11 / 12).
- **Ресурсы**: 1–2 vCPU, 1–2 ГБ RAM, 15–20 ГБ SSD.
- **Открытые порты в Firewall / Security Groups**:
  - `22` (SSH — управление)
  - `80` (HTTP — веб-доступ)
  - `443` (HTTPS — защищенный веб-доступ)
  - `3000` (Node.js бэкенд, если без Nginx)

---

## ⚡ 2. Пошаговая установка за 5 минут

### Шаг 1: Подключение к серверу и обновление пакетов
Подключитесь к VPS по SSH:
```bash
ssh root@<IP_ВАШЕГО_VPS>
```
Обновите пакеты системы:
```bash
apt update && apt upgrade -y
```

### Шаг 2: Установка Node.js 22 LTS, Git и Nginx
Выполните установку Node.js 22 и вспомогательных утилит:
```bash
# Установка curl и git
apt install -y curl git build-essential nginx

# Установка Node.js 22 LTS (NodeSource)
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs

# Проверка версий
node -v    # Должно быть v22.x.x
npm -v     # Должно быть v10.x.x

# Установка глобального менеджера процессов PM2
npm install -g pm2
```

### Шаг 3: Клонирование репозитория
Склонируйте проект в рабочую директорию `/var/www/kabancloud`:
```bash
git clone https://github.com/nomer156/kabancloud.git /var/www/kabancloud
cd /var/www/kabancloud
```

### Шаг 4: Установка зависимостей и сборка фронтенда
```bash
# Установка зависимостей
npm install

# Сборка продакшн-бандла Vite
npm run build
```
После сборки появится оптимизированная директория `/var/www/kabancloud/dist`.

### Шаг 5: Запуск сервера через PM2
Запустите бэкенд `server.js` через подготовленный конфигурационный файл `ecosystem.config.cjs`:
```bash
pm2 start ecosystem.config.cjs

# Сохранение списка процессов для автозапуска при перезагрузке VPS
pm2 save
pm2 startup
# (Выполните сгенерированную команду sudo env PATH=... если PM2 попросит)
```

Проверка статуса:
```bash
pm2 status
pm2 logs kabancloud --lines 30
```

### Шаг 6: Настройка Nginx (Реверс-прокси)
Скопируйте подготовленный конфигурационный файл `nginx_vps.conf`:
```bash
cp /var/www/kabancloud/nginx_vps.conf /etc/nginx/sites-available/kabancloud

# Замените your-vps-ip.com на реальный IP или домен сервера:
nano /etc/nginx/sites-available/kabancloud

# Активация сайта
ln -s /etc/nginx/sites-available/kabancloud /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default

# Проверка конфигурации и перезапуск Nginx
nginx -t
systemctl restart nginx
```

Готово! Откройте в браузере: `http://<IP_ВАШЕГО_VPS>/`

## 🔒 3. Установка бесплатного SSL-сертификата (Let's Encrypt / HTTPS)

Если к VPS привязан домен (например, `kaban.ufanet.ru`):
```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d kaban.ufanet.ru
```
Certbot автоматически сконфигурирует SSL в Nginx и настроит автопродление каждые 90 дней.

## 👑 4. Доступ главного администратора (`admin`)

В системе создан встроенный профиль администратора с наивысшим 10-м уровнем доступа:
- **Логин**: `admin`
- **Уровень роли**: `10` (Полный доступ)
- **Возможности**:
  - Управление матрицей прав доступа для всех уровней (1..10) во вкладке «Настройки» -> «Роли и уровни».
  - Добавление и удаление смежных отделов компании.
  - Удаление любых карточек, перемещение по колонкам, назначение ответственных.
  - Просмотр журнала аудита ИБ (`audit.log`).
- **Быстрый вход**: В окне входа нажмите кнопку **«👑 Войти как admin»** в верхней части модального окна.

## 💻 5. Авторизация по имени устройства (`vlxproject00` .. `vlxproject99`)

У каждого компьютера в локальной сети Уфанет имя хоста задано по шаблону `vlxprojectXX`. Система поддерживает три режима работы с ними:

### Вариант А: Автоматический вход через ярлык Windows (.bat) — Рекомендуемый
1. В корне репозитория подготовлен файл [`kaban_desktop_shortcut.bat`](file:///e:/kaban2/kaban_desktop_shortcut.bat).
2. Отредактируйте строку с адресом сервера:
   ```cmd
   set SERVER_URL=http://<IP_ВАШЕГО_VPS>
   ```
3. Распространите этот `.bat` файл на рабочие столы инженеров (вручную или через GPO контроллера домена).
4. **Как это работает**:
   - При двойном клике Windows автоматически раскрывает `%COMPUTERNAME%` в реальное имя машины (например, `vlxproject04`).
   - Открывается ссылка `http://<IP_VPS>/?pc=vlxproject04`.
   - KabanCloud мгновенно определяет рабочее место, авторизует инженера и открывает его канбан-доску **без единого клика**.

### Вариант Б: Вход через интерфейс в 1 клик
1. На странице входа в блоке «Вход по имени рабочего ПК» введите номер (например, `04`) или имя `vlxproject04`.
2. Нажмите «Войти по ПК».
3. Галочка «Запомнить ПК» включена по умолчанию — браузер запомнит это устройство, и при следующих визитах вход будет происходить автоматически.

## 🔄 6. Обновление версии на VPS

При выходе новой версии в GitHub репозитории:
```bash
cd /var/www/kabancloud
git pull origin main
npm install
npm run build
pm2 restart kabancloud
```
База данных `data/ufanet_db.json` и логи сохраняются автоматически и не затираются.

## 💾 7. Резервное копирование базы данных

База данных хранится в защищенном файле `/var/www/kabancloud/data/ufanet_db.json`.
Сервер каждые 30 минут автоматически делает резервные копии в `/var/www/kabancloud/data/backups/`.

Для дополнительного ежедневного бэкапа по расписанию настройте cron:
```bash
crontab -e
# Добавьте строку (бэкап каждую ночь в 03:00):
0 3 * * * cp /var/www/kabancloud/data/ufanet_db.json /var/backups/kaban_$(date +\%Y\%m\%d).json
```

## 🛡️ 8. Переход из общедоступного режима в строгий корпоративный (Чек-лист при запуске боевого VPS)

> **Статус на время тестирования (Текущий режим)**:
> Сервер настроен как **общедоступный (Open Access)**:
> - Вход возможен с любого домашнего компьютера, телефона или ноутбука без обязательного указания имени ПК `vlxproject..`.
> - Любой сотрудник выбирает свой профиль в 1 клик или входит через кнопку «👑 Войти как admin».
> - Нет жестких блокировок по IP или подсетям, чтобы вся команда могла свободно тестировать функции из дома и в офисе.

### 📋 Список шагов при переносе на боевой корпоративный VPS:

#### Шаг 1: Ограничение доступа по IP (Белый список подсетей Уфанет в Nginx)
В файле `/etc/nginx/sites-available/kabancloud` настройте директивы ограничения доступа, чтобы закрыть сервис от внешнего интернета:
```nginx
location / {
    # Доступ только из корпоративной сети Уфанет и филиалов:
    allow 10.0.0.0/8;        # Внутренний корпоративный диапазон
    allow 172.16.0.0/12;     # VLAN филиалов / VPN
    allow 192.168.0.0/16;    # Локальные подсети офисов
    # allow 89.189.xxx.xxx;  # Внешний IP офиса (при необходимости)
    deny all;                # Все остальные блокируются (403 Forbidden)

    root /var/www/kabancloud/dist;
    index index.html;
    try_files $uri $uri/ /index.html;
}
```
После изменения перезапустите Nginx:
```bash
nginx -t && systemctl restart nginx
```

#### Шаг 2: Распространение корпоративного .bat ярлыка на компьютеры инженеров
1. Скопируйте файл `kaban_desktop_shortcut.bat` в общую сетевую папку филиала (например `\\ufanet-srv\software\kaban\`).
2. В файле укажите боевой адрес:
   ```cmd
   set SERVER_URL=http://kaban.core.ufanet.ru
   ```
3. Разместите ярлык на рабочих столах инженеров (проектировщиков, сметчиков, монтажников, сварщиков) через Active Directory GPO или вручную.
4. При запуске Windows автоматически передаст имя машины `%COMPUTERNAME%` (например, `vlxproject04`), и система мгновенно откроет профиль инженера без авторизации.

#### Шаг 3: Включение верификации сотрудников начальниками отделов (Chief Approval)
- При первом входе новый сотрудник виден в общем списке, но имеет отметку «Требует подтверждения».
- Начальник соответствующего отдела (роль 10 уровня):
  1. Открывает окно «Сотрудники отдела».
  2. Проверяет должность, ФИО и привязку ПК.
  3. Нажимает кнопку «✓ Подтвердить сотрудника».
  4. После этого сотрудник получает полноценный рабочий доступ к доске и чатам отдела.

#### Шаг 4: Защита учетной записи `admin`
- Главный администратор входит в систему под логином `admin`.
- В окне настроек матрицы прав проверяет уровни 1..10.
- В окне «Заявки на доступ» утверждает заявки начальников отделов на получение 10 уровня.

#### Шаг 5: Мониторинг журнала безопасности ИБ
Журнал событий информационной безопасности пишется в реальном времени в `/var/www/kabancloud/data/logs/audit.log`. Просмотр последних записей:
```bash
tail -n 50 -f /var/www/kabancloud/data/logs/audit.log
```
