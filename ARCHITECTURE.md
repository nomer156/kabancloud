# АРХИТЕКТУРА СИСТЕМЫ • УФАНЕТ KABAN

> **Статус документа:** Архитектурная спецификация и регламент потоков данных.

---

## 1. Концепция и технологический стек

Система представляет собой распределённую корпоративную канбан-доску реального времени (аналог YouGile / Jira), спроектированную специально под регламенты и бизнес-процессы АО «Уфанет».

### Стек технологий:
- **Frontend:** React 19, Vite, Lucide React (иконки), Canvas Confetti.
- **Стилизация:** Чистый CSS с CSS-переменными (`src/index.css`), фирменная палитра Уфанет (`#ff6600` акцент, `#0b0f19` глубокий фон, `#141c2c` карточки).
- **Backend:** Node.js HTTP сервер (`server.js`), работающий без сторонних тяжелых фреймворков.
- **База данных:** Транзакционная JSON-база (`data/ufanet_db.json`) с контрольными суммами и автоматическим созданием резервных копий при каждом сохранении в `data/backups/`.
- **Шина реального времени:** Server-Sent Events (SSE, эндпоинт `/api/events`) для мгновенного многопользовательского обновления всех клиентов без нагрузки на сеть.

## 2. Архитектура потоков данных (Data Flows)

```
┌────────────────────────────────────────────────────────┐
│                   React Frontend                       │
│  (App.jsx -> KanbanColumn -> TaskCard / ChatPanel)    │
└───────────────▲──────────────────────────┬─────────────┘
                │ SSE                      │ REST (fetch)
                │ (/api/events)            │ (GET, POST, PATCH, DELETE)
┌───────────────┴──────────────────────────▼─────────────┐
│                    Node.js Backend                     │
│                      (server.js)                       │
│  ┌──────────────────┐               ┌───────────────┐  │
│  │ SSE Event Bus    │               │ REST Router   │  │
│  │ (broadcastEvent) │               │ & Auth Guard  │  │
│  └──────────────────┘               └───────┬───────┘  │
└─────────────────────────────────────────────┼──────────┘
                                              │ File I/O
                                      ┌───────▼───────┐
                                      │ ufanet_db.json│
                                      │ & backups/    │
                                      └───────────────┘
```

### Поток 1: Создание и сохранение задачи
1. Пользователь заполняет поля в `TaskModal.jsx` или `TaskDetailView.jsx`.
2. Вызывается `onSaveTask(payload)` в `App.jsx`.
3. `App.jsx` делает оптимистичное обновление локального массива `tasks`, гарантируя мгновенный отклик интерфейса (Zero Latency UI).
4. `saveTask(payload)` в `src/lib/api.js` отправляет `POST /api/tasks`.
5. `server.js` валидирует поля, сохраняет задачу в `ufanet_db.json`, создает снапшот в `data/backups/` и транслирует событие `TASK_UPDATED` всем подключенным клиентам по SSE.
6. Другие пользователи получают обновленную карточку «на лету» без перезагрузки страницы.

### Поток 2: Иерархия подзадач (Рекурсивное дерево)
- В системе **отсутствуют чекбоксы подзадач**. Подзадача — это полноценная сущность `task`, у которой поле `parent_task_id` указывает на ID родительской задачи.
- Перетаскивание карточки «Б» на карточку «А» устанавливает `taskB.parent_task_id = taskA.id`.
- Перетаскивание подзадачи «Б» на любую колонку доски сбрасывает `taskB.parent_task_id = null`, вынося её в корень доски.
- Компонент `NestedSubtaskCard` в `TaskCard.jsx` рекурсивно отображает вложенные подзадачи любой глубины с кнопками сворачивания/разворачивания, переключения статуса и назначения исполнителя.

### Поток 3: Чат, комментарии и умные упоминания (@mentions)
1. Пользователь вводит текст в `TaskChatPanel.jsx` или общем `ChatSidebar.jsx`.
2. Ввод символа `@` открывает `MentionAutocompleteDropdown` со списком инженеров отдела и опцией `@все`.
3. При отправке комментария функция `extractMentionTargets` извлекает ID адресатов.
4. Отправляется уведомление в `/api/notifications`.
5. Сервер рассылает событие `NEW_MENTION` целевым сотрудникам.
6. В `Header.jsx` у упомянутых сотрудников загорается колокольчик с числом непрочитанных упоминаний и воспроизводится звуковой сигнал `playSound('mention')`. Автор сообщения в свой колокольчик уведомление **не получает**.

### Поток 4: Работа с файлами и сетевыми папками Windows (DFS)
- Для открытия чертежей на серверах компании клиент вызывает `openFolderInExplorer(networkPath)` из `src/lib/api.js`.
- Запрос поступает на `POST /api/open-folder` в `server.js`.
- Сервер санитизирует путь (блокирует исполняемые расширения `.exe`, `.bat`, `.cmd`, `.ps1` и командные инъекции) и вызывает встроенный системный процесс:
  - В Windows: `explorer.exe <safePath>`
  - В Linux (виртуальная машина): эмулирует успешный ответ и протоколирует обращение в журнал аудита.
- Если браузер заблокировал запуск Проводника, интерфейс копирует путь в буфер обмена с всплывающей подсказкой: `Win+R -> Ctrl+V -> Enter`.

### Поток 5: Авторизация и защита экрана гостя (Guest Lock Screen)
- Если в `localStorage` отсутствует валидный объект `kaban_current_user`, приложение входит в режим защиты данных:
  - Основное рабочее пространство доски (колонки, задачи, чаты, фильтры) **не монтируется в DOM**.
  - Отображается экран-заставка с корпоративным логотипом и кнопкой «Войти в систему».
  - После успешного входа через `AuthModal.jsx` пользователь сохраняется в стейт, и доска разблокируется.

## 3. Ключевые архитектурные ограничения и принципы

1. **Чистота хуков React 19:**
   - Все хуки (`useState`, `useEffect`, `useMemo`, `useCallback`, `useRef`) объявляются **строго в самом начале компонента**, до любых условий `if (!item) return null;`.
   - Запрещено вызывать хуки внутри циклов, условий или вложенных функций.

2. **Защита от утечек и циклических зависимостей:**
   - Для глобальных событий (`dragend`, `keydown`, `mousedown`) обработчики в `useEffect` обязаны возвращать функцию очистки `return () => window.removeEventListener(...)`.

3. **Корпоративная палитра Ufanet:**
   - Основной акцентный цвет: `#ff6600` (оранжевый Уфанет).
   - Цвет успешных действий / таймера: `#10b981` (изумрудный).
   - Цвет ошибок / срочных задач: `#ef4444` (красный).
   - Цвет зеркалирования отделов: `#8b5cf6` (фиолетовый).
   - Фон элементов управления: `#1a2234` / `#131d2e` с полупрозрачными границами `rgba(255, 255, 255, 0.08)`.

4. **Разграничение ролей (RBAC):**
   - Уровень 10 (Администратор / Начальник): полное управление всеми марками, сотрудниками, настройками колонок и матрицей прав.
   - Уровень 1–7 (Инженер): создание и выполнение задач, ведение чата, списание часов, просмотр структуры без права удаления чужих аккаунтов или изменения этапов отдела.
